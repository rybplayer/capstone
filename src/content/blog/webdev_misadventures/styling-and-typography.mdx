## The color palette

I spent more time thinking about the site's color palette than any other design decision. This was largely because I wanted a palette that:

1. Had a <span className="text-primary font-bold">primary color</span> that was visible in both light and dark mode.
2. Had a <span className="text-primary font-bold">primary color</span> with <span className="text-muted font-bold">many</span> <span className="text-accent font-bold">subtle</span> <span className="text-secondary font-bold">shades</span>, making light and dark mode palettes easy.
3. Had a wide available [color gamut](https://en.wikipedia.org/wiki/Gamut) on most displays.

I did this by [experimenting](https://oklch.com/#0.5,0.1,130,100) with [`okclh(L C H / a)`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/oklch), which controls

- `L`, perceived lightness, dark to bright $[0,1]$;
- `C`, chroma, dull to vivid $[0,\infty)$;
- `H`, hue, or the color angle in polar coordinates $[0^\circ,360^\circ]$;
- `a`, alpha, transparent to opaque $[0,1]$.

To create a cohesive palette, I wanted all colors to have the same hue color. Furthermore, between dark and light mode, different colors should have the same relative chroma, but have "inverted" lightness.

## Styling images

Black and white images are automatically inverted on light/dark mode though CSS' [`invert`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/filter-function/invert).

Post banners get special treatment. The art, text, and watermark are stored as an svg with transparent background. Between light and dark mode, I just swap out the background color. Here's what the banner looks like on both themes:

<div class="not-prose xs:flex-row xs:justify-between flex flex-col items-center gap-4">
  <img
    src={Banner.src}
    alt="Banner art on light background"
    class="xs:w-[48%] w-full bg-[var(--banner-light)]"
  />
  <img
    src={Banner.src}
    alt="Banner art on dark background"
    class="xs:w-[48%] w-full bg-[var(--banner-dark)]"
  />
</div>

Unfortunately, open graph previews don't work well with this. So I supply the same banner with background for this.

## Styling text

Almost all [Markdown](https://www.markdownguide.org/) syntax is built-in. This includes **bold**, _italics_, $\text{equations}$, and `code`. Inline code highlighting is done by [rehype-pretty-code](https://github.com/rehype-pretty/rehype-pretty-code). Spoiler tags like <Spoiler>this</Spoiler> are custom inline components.

Sections are done with `#`, `##`, and so on. Tables are just like markdown:

| Column 1 | Column 2 |
| -------- | -------- |
| Value 1  | Value 2  |
| Value 3  | Value 4  |

Code blocks are styled by [Expressive Code](https://expressive-code.com/), which allow me to do things like:

```js title="line-markers.js" del={2} ins={3-4} {14} collapse={5-13}
function demo() {
  console.log('this line is marked as deleted')
  // This line and the next one are marked as inserted
  console.log('this is the second inserted line')
  console.log('C')
  console.log('O')
  console.log('L')
  console.log('L')
  console.log('A')
  console.log('P')
  console.log('S')
  console.log('E')
  console.log('D')
  return 'this line is marked and all code in between is collapsed'
}
```

Big thanks to [Erudite](https://astro-erudite.vercel.app/blog/rehype-patch) for making [Expressive Code](https://expressive-code.com/) work with [rehype-pretty-code](https://github.com/rehype-pretty/rehype-pretty-code). Both packages are essential as Expressive Code doesn't decorate inline code but rehype-pretty-code's code blocks aren't as customizable as Expressive Code's.

## Typography

The current default font is [Inter](https://fonts.google.com/specimen/Inter) and the `mono` font is [Geist Mono](https://fonts.google.com/specimen/Geist+Mono). I like how modern and readable these fonts are. They're also [variable fonts](https://en.wikipedia.org/wiki/Variable_font).

[Serif](https://en.wikipedia.org/wiki/Serif) vs [sans-serif](https://en.wikipedia.org/wiki/Sans-serif) was an unexpected point of contention in this website's design. Half of the people I asked feedback from preferred sans-serif, because it looks modern and clean. The other half argued serif was more academic and better suited my purposes.

Here's a screenshot of an old version of the site with serif font:

<img src={Serif.src} class="w-full max-w-md"></img>

Honestly, I thought it looked disgusting and too much like the default font.

Other typography things: Titles are in titlecase. Sections have the first word and proper nouns capitalized. All files and technical names should be slugified (lowercase with `-` as spaces).
